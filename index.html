CS 응대 에이전트 · 지식베이스 RAG

종합설계1 · 팀장 · 4명 · 2026.09~ 진행 중

프로젝트 개요
악성 민원 대응을 주제로, 고객 문의 메일을 네 에이전트(접수, 답장, 검수, 인계)가 처리하고 담당자가 승인하는 CS 응대 에이전트입니다.
맡은 일
팀장으로 진행을 맡으면서, 접수 에이전트가 지식베이스(KB) 전체를 읽던 구조를 문의와 비슷한 답변만 벡터 DB에서 가져오도록 RAG로 바꿨습니다. 같은 평가 세트로 시간, 토큰, 정확도를 비교했고 지금은 KB를 늘리고 있습니다.
트러블슈팅
실제 LLM으로 비교하니 결과 정확도가 0.839에서 0.774로 떨어졌습니다. Recall@5가 1.0이라 검색 누락은 아니었고, 답변 6개 중 5개만 뽑히는 채널에서 근거 하나가 빠지면 에이전트가 사람에게 넘기는 걸 찾아 정확도가 아니라 자동 처리율 손실로 나눠 기록했습니다.
사용 기술
Node.js Amazon Bedrock Cohere Embed v4 PostgreSQL pgvector Docker AWS IAM Claude API

프로젝트 개요
5명이 함께 하는 게임의 주간 수익을 기여도대로 나누는 정산 웹앱입니다. 디스코드로 주고받던 숫자를 한곳에 모아 주차별로 쌓고 확정합니다.

결과가 맞는지 확인하는 방법

  1. 요건을 나눠서 봅니다

    공개SW프로젝트에서 졸업 가능 여부만 보면 맞아 보였는데, 요건별로 나누니 세부까지 맞은 데이터는 170개 중 2개였습니다. 그래서 요건마다 충족 여부가 따로 나오게 Z3 Solver로 검증했습니다.

  2. 기존 값과 1원까지 맞춥니다

    정산 웹앱을 옮긴 뒤 기존 시트의 정산액 15개를 1원 단위까지 대조하고 나서야 이식을 끝냈습니다. 지금은 push마다 테스트 56개가 GitHub Actions에서 돕니다.

  3. 감시하는 쪽도 시험합니다

    Jenkins와 SonarQube로 CI를 만든 뒤 일부러 틀린 Python, C, JavaScript 코드를 push해 분석이 잡는지 봤습니다. 분석에서 빠지는 코드가 있어 분석 설정을 보완했습니다.
